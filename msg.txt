engine: the split chunk's wait is NI_ANE_SPLIT_WAIT_MS, and a test gives a chunk up (#426)

Engine::wait_split bounds a GPU + Neural Engine split chunk with a fixed 60 s: the split is retired, the
GPU's waits are released and the chunk reruns on the GPU alone. Nothing had ever run that branch (issue
#426): a job that started and stalled is retired by its own 2 s watchdog first, and a test cannot wait out
a real minute to reach the bound behind it.

The bound is now NI_ANE_SPLIT_WAIT_MS (default 60000, read per call, so the shipped behaviour and its log
line - "has not finished in 60 s" - are unchanged; a shortened bound prints in ms).

tests/test_ane_split_abort.py (model folder, GPU, Neural Engine; it takes the GPU lock) runs it at 250 ms
with NI_ANE_FAULT=0 on three fresh servers, each with its own KAPITSA_HOME and greedy replies:

  0. NI_ANE=0: the two prompts' replies on the GPU alone, the control.
  1. the split on: both prompts run split chunks that hold (the busy line counts evaluations), no chunk
     given up.
  2. the fault: the bound runs out first, the split is given up with the abort's reason (not the
     watchdog's), the chunk reruns on the GPU, and both prompts give the control's replies again. Each
     line is logged once and the second prompt neither splits nor bounds again.

The legs hold NI_ANE_MIN_ROWS=512 and use a 700-row prompt so the chunk takes the split's single-lane
schedule, the one where the GPU's command buffer waits on the job: on the wavefront schedule (two row
halves, from 256 rows) the GPU side does not wait and the chunk is given up by Handoff::finish's own 2 s
bound instead. The legs are otherwise the model's defaults.

Run on the M5 Pro with qwen3.5-4b-4bit-mtp (24-token replies, NI_ANE_FAULT=0, NI_ANE_SPLIT_WAIT_MS=250):
"NI_ANE: a split prefill chunk has not finished in 250 ms; giving up the Neural Engine split" once, e.wait()
returning 175 ms later, "Neural Engine FFN split stopped (a split chunk did not finish within 250 ms); this
chunk reruns on the GPU, which runs the prefill FFN alone from now on" once, the busy line "over 1 split
chunks (0 evaluations)", and both prompts' replies equal to the NI_ANE=0 run. The faulted prompt took
2.5 s against 0.4 s for the control and 0.4 s for the prompt after it: the bound, then Handoff::finish's
2 s bound for the job that never reports, then the GPU rerun. The 60 s default itself is the same code
path with a longer wait.

No numerics change: the diff reads the environment variable and formats the log line; nothing else on the
path changes. docs/usage.md documents the knob, AGENTS.md lists the test with the other model/GPU ones.

Closes #426.
